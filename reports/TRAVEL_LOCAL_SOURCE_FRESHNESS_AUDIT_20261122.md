# Travel Local — source, feed, freshness and retention audit

**Date:** 2026-11-22
**Accepted source baseline:** `6431494c398baefc08a14354d871519206b0d764` (`main`)
**Scope:** Main tab > Quick Weather > Travel Local, city JSON collector, scheduling, publication and UI eligibility.

## Source-first findings

1. Four canonical travel JSON inputs under `public/data/travel-local-{chennai,trichy,muscat,colombo}.json` were generated on **2026-07-21** and contained **zero stories**. The `docs/data` copies were also July snapshots, but `deploy.yml` publishes Vite `dist` from `public`; `docs` is not the deployment authority.
2. The collector workflow `.github/workflows/travel-local-news.yml` was absent from the baseline tree even though `deploy.yml` named “Travel local news prefetch” as a downstream deployment trigger and a manifest expected the file.
3. `scripts/collect_travel_local_news.mjs` used `/<item>([sS]*?)<\/item>/g`; `[sS]` only matches literal letters s/S, not multiline XML. The collector also populated `city` and `country` directly from the selected query, manufacturing event geography.
4. The browser-side fetch default was `/data`, rooted at the domain rather than GitHub Pages' `/NWv-7/` subpath. `vite.config.js` uses `base: './'`, requiring a relative `./data` resource path.
5. `TravelLocalStories` required city matching but not a publication timestamp. `rankStoriesForLocation` could display older articles from general news datasets indefinitely.
6. The source policy offered `maxAgeMinutes=180` and `staleAfterMinutes=360`, yet neither source receipt age nor individual story expiration was enforced. Queries could target general country news and `30d` windows.
7. The workflow test used `it.skipIf(!fs.existsSync(TRAVEL_WORKFLOW))`, silently skipping the missing collector when it mattered most.
8. Fresh `public/newsdata/sections_latest.json` was available at the baseline and reported `window.retainHours=36`, with regional `trichy` and `muscat` arrays and publication timestamps. These are viable city-scoped **fallback candidates**, but not permission to label undated or country-only stories as recent city news.

## Implemented corrective contract

| Layer | Policy |
| --- | --- |
| Collection | Google News city-scoped RSS searches; no country-wide city impersonation |
| Parsing | RSS `<item>` multiline-safe parser, real `pubDate` and `source`; never fabricate city/country |
| Acceptance | Real source publication timestamp, matched event city, deduplicated URL |
| Retention | 36 hours from original publication; future timestamp drift at most five minutes; undated rejected |
| Feed receipt | Generated by successful RSS checks; reject snapshots older than 12 hours |
| Scheduling | GitHub Actions `Travel local news prefetch` every 3 hours and manually dispatchable |
| Failure | Zero successful RSS queries fails without overwriting last published payload |
| Empty feed | Valid empty receipt after successful RSS query; panel displays honest no-current-match state |
| Cap | Maximum 30 accepted stories per city |
| Publication | Validate all four city JSON documents; commit/push to `main`; existing Pages `workflow_run` trigger deploys |
| Browser | Fetch `./data/travel-local-CITY.json`, no-store; reject wrong/stale receipts and expired stories |
| Main UI | Filter date and city for final cards; show article publication age; refresh on visibility and every 5 minutes |
| Scope | Keep Quick Weather selection and unrelated manual travel-city preferences independent |

## First real-source acceptance and subsequent geographic correction

**Collector run:** https://github.com/reallakshman19/NWv-7/actions/runs/44986353223
**Published data commit:** `00312f03b7e7d18d572cf165d793fbb733369eee`
**Collected 2026-11-22 04:44 UTC:** Chennai 30, Trichy 1, Muscat 14, Colombo 10; all four reported five successful Google News RSS queries and zero fetch errors. This closes the old empty/missing collection defect.

**Additional live-content finding:** Google News RSS titles include ` - Publisher` suffixes. Titles from `Muscat Daily` were falsely admitted as Muscat event news (for example an OCCI voting story whose body title did not name Muscat). A Singapore tourism article mentioning **Muscat grapes** was also admitted as a city headline. Colombo's continuously refreshed Flightradar24 arrivals/departures listings are not current editorial news. These are source-identity errors, not timestamp errors.

**Follow-up correction:** Strip the known RSS publisher suffix before scoring and display; preserve publisher separately as source. Exclude the grape/wine cultivar sense of Muscat from location relevance; reject evergreen flight-tracker listing items, and certify those negative examples. Extend workflow bootstrap triggers to source/parser/geography code changes so published city JSON can be regenerated promptly.

The initial live collector success is **not** proof that all article geography is correct. Release acceptance requires the follow-up source-cleaning check and refreshed city JSON.
